# Bun移行実験ノート

実験開始日: 2026-05-05
ブランチ: `experiment-bun`

## 目的

1. Bunを実際に触って学ぶ
2. sitesnapがBunで成立するか検証する(特にPlaywrightの動作)
3. 段階的に進めて技術的ボトルネックの位置を切り分ける

## スコープ(3段階)

| 段階 | 内容 |
|---|---|
| ① パッケージマネージャ | `pnpm` → `bun install`への切替 |
| ② ランタイム | shebangとscriptsを`node` → `bun`に変更 |
| ③ TypeScript化 | `.mjs` → `.ts`、テストを`bun:test`に移行 |

## 評価基準(各段階共通)

- 既存テストが通る
- `sitesnap site <URL>`で実機スクショが撮れる(②以降の最重要項目)
- 体感速度に明らかな悪化がない

## 判断ルール

| 結果 | 対応 |
|---|---|
| ①②③全部成功 | mainにマージ |
| ①②成功・③失敗 | ③のコミットを捨てて①②だけmainへ |
| ①成功・②失敗 | ①だけmainへ(または全部捨てる) |
| ①から壊れる | ブランチ削除して撤退 |

## 結果

### ① パッケージマネージャ
- 状態: ✅ 成功
- 所感:
  - `bun install`は1.93秒で完了。pnpmより明らかに速い
  - 全42テストが`bun run test`(裏ではnode --test)で通過
  - 引っかかりなし

### ② ランタイム
- 状態: ✅ 成功
- 所感:
  - 事前予想は「五分五分」だったが、Bun 1.3.13ではPlaywrightが普通に動いた
  - `bun cli.mjs page https://example.com`でデスクトップ・モバイル両方のPNGが正常生成
  - Bunのchild_process互換とPlaywright連携は実用レベルに達している模様

### ③ TypeScript化
- 状態: ✅ 成功
- 所感:
  - `.mjs` → `.ts`は機械的リネームで完了。Bunが`.ts`を直接実行するのでビルド不要
  - `bun test`はnode:test APIを大半サポートしている(38/42テストがそのまま通った)
  - **唯一の非互換は`mock.fn`** — `node:test`のモック関数がBunのアダプタで未実装
  - 該当箇所はモックの呼び出し追跡を手動配列で行っていたため、`mock.fn`ラッパーを外すだけで解決
  - src/* には型注釈をまだ付けていない(ファイル拡張子だけTSで中身は実質JSのまま) — 必要なら後追いで追加可能

## 学び(Bun全般)

- **インストール**: brewで簡単に入る。1.3.13で動作確認
- **node:test互換性**: 期待以上に良い。mock以外はそのまま動く
- **Playwright**: 心配していたが現バージョンでは動作。継続的な検証は必要
- **実行速度**: 起動時間は体感で速いが、CLI 1回起動分なので大きなインパクトはない

## Stage 2の単独可搬性に関する注意

事後レビューで判明した点として、**Stage 2(7fe79cd)単独でmainにマージするのは推奨できない**:

- Stage 2は`cli.mjs`のshebangを`#!/usr/bin/env bun`に変更したが、`engines.node: ">=22"`と`bin: cli.mjs`のままにしている
- これらの整合性(`engines.bun`への切替、bin/files更新)はStage 3で初めて行われた
- 結果として、Stage 2単体ではpackage.jsonのメタデータが内部的に矛盾する状態になっている

そのため判断ルールの「①②成功・③失敗 → ①②だけmainへ」は成立しない。実際に起き得る撤退パターンは:
- ①だけmainへ(Stage 2以降を全て破棄)
- ①②③全部成功 → 全部mainへ
- ①②③のどこかで失敗 → 全部破棄

次回類似の実験を行う際は、各stageのコミット内容を「単独で公開可能な状態」に整える(または明示的に「中間状態は実験用」と記録する)と良い。

## 最終判断

**全段階成功。`experiment-bun`をmainにマージする価値あり。**

ただしマージ前に検討すべき点:
1. **配布形態**: 現状bin=cli.tsなので、ユーザーにBunインストールを要求することになる。npm再公開する場合はこれで良いか要判断
2. **CI**: `.github/workflows/`内のpnpm/nodeをbunに更新する必要がある
3. **README/AGENTS.md**: インストール手順や開発手順をBunベースに書き直す必要がある
4. **Node完全廃止か併用か**: 現状はBun前提のセットアップ。Node環境でも動かすなら追加の互換層が必要
